# Admin screen and API matrix

This matrix reconciles the client ADM-001 through ADM-018 screen inventory with the current backend. Client screen routes such as `/admin/users` are frontend routes; API routes below use the `/api/v1` base. Admin API aliases call the shared Module 1 services and tables.

| Screen                             | UI route                                   | Backend API flow                                                                                 | Status and notes                                                                                                                                                                                                                                                                                                                                                                                                            |
| ---------------------------------- | ------------------------------------------ | ------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ADM-001 Admin Login                | `/admin/login`                             | Existing Auth0 Universal Login; then `GET /auth/me`                                              | No admin sign-up or separate auth API. Shared tenant, separate admin Auth0 app, mandatory MFA, backend checks admin client and MFA claims.                                                                                                                                                                                                                                                                                  |
| ADM-002 Admin Dashboard            | `/admin`                                   | `GET /admin/dashboard`                                                                           | Implemented from shared user/RBAC/settings/flags/audit data.                                                                                                                                                                                                                                                                                                                                                                |
| ADM-003 User Management            | `/admin/users`                             | `GET /admin/users`; `PATCH /admin/users/:userId/status`; `POST /admin/users/:userId/lock`; `POST .../unlock`; `POST .../reinstate[/approve|/reject]` | List filters include user ID, name/email or general search, mobile, status, verification, role, and created date range. Status supports ACTIVE, DISABLED, SUSPENDED and requires a reason; suspension also requires a category. Restricted reinstatement requires SUPER_ADMIN approval. Lock/unlock routes record reasons and invalidate older Examinity API tokens. |
| ADM-004 User Details               | `/admin/users/[userId]`                    | `GET /admin/users/:userId`                                                                       | Returns profile, verification, status, roles and timestamps; sensitive credentials are not exposed.                                                                                                                                                                                                                                                                                                                         |
| ADM-005 User Activity              | `/admin/users/[userId]/activity`           | `GET /admin/audit-logs?target_user_id=:userId` and `GET /admin/audit-logs?actor_user_id=:userId` | Reuses central immutable audit history. Merge and deduplicate by audit ID. It returns recorded account/admin events; it does not invent login/device data.                                                                                                                                                                                                                                                                  |
| ADM-006 User Role Assignment       | `/admin/users/[userId]/roles`              | `GET/POST /admin/users/:userId/roles`; `DELETE /admin/users/:userId/roles/:roleId`               | Assignment and revocation require a reason; assignment also accepts optional start/end dates. SUPER_ADMIN cannot be assigned through this route. Current ADMIN baseline lacks role assignment read/write permissions, so operations are SUPER_ADMIN-only. DELETE revokes an assignment; it does not delete the user or role. Organization scope is not applicable in the current schema. |
| ADM-007 Role Management            | `/admin/access/roles`                      | `GET /admin/roles`                                                                               | Initial approved roles only: SUPER_ADMIN, ADMIN, AUTHENTICATED_USER.                                                                                                                                                                                                                                                                                                                                                        |
| ADM-008 Role Details               | `/admin/access/roles/[roleId]`             | `GET /admin/roles/:roleId`                                                                       | Includes protected/system/assignable fields, permissions, and assignment history. Assignment reason is retained in audit metadata.                                                                                                                                                                                                                                                                                          |
| ADM-009 Permission Management      | `/admin/access/permissions`                | `GET /admin/permissions`                                                                         | Permission responses include module/resource/action and system status.                                                                                                                                                                                                                                                                                                                                                      |
| ADM-010 Role-Permission Mapping    | `/admin/access/roles/[roleId]/permissions` | `GET/PUT /admin/roles/:roleId/permissions`                                                       | System roles are protected. The backend rejects adding permissions the acting administrator does not hold.                                                                                                                                                                                                                                                                                                                  |
| ADM-011 Audit Log Viewer           | `/admin/audit-logs`                        | `GET /admin/audit-logs`                                                                          | Supports actor, action, resource type/id, target user, outcome, date range, and pagination. Organization filter is unavailable because no organization scope exists.                                                                                                                                                                                                                                                        |
| ADM-012 Audit Log Details          | `/admin/audit-logs/[auditId]`              | `GET /admin/audit-logs/:auditId`                                                                 | Read-only detail includes stored actor, action/resource, before/after metadata, result, request context and timestamps where collected.                                                                                                                                                                                                                                                                                     |
| ADM-013 Platform Configuration     | `/admin/settings`                          | `GET /admin/settings`                                                                            | Lists allowlisted, non-secret settings only.                                                                                                                                                                                                                                                                                                                                                                                |
| ADM-014 Configuration Details/Edit | `/admin/settings/[settingKey]`             | `GET/PATCH /admin/settings/:settingKey`; `PATCH .../:settingKey/status`                          | PATCH requires a reason and current version; values are validated against the setting catalogue and audited. Status changes between ACTIVE and INACTIVE are versioned and audited.                                                                                                                                                                                                                                             |
| ADM-015 Feature Flag Management    | `/admin/feature-flags`                     | `GET /admin/feature-flags`                                                                       | Lists registered simple flags; no rollout or targeting behavior.                                                                                                                                                                                                                                                                                                                                                            |
| ADM-016 Feature Flag Details/Edit  | `/admin/feature-flags/[flagId]`            | `GET/PATCH /admin/feature-flags/:flagKey`; `PATCH .../:flagKey/status`                            | The current schema identifies flags by unique `flag_key`, not UUID `flagId`. Value and status updates require the current version and a reason; changes are audited.                                                                                                                                                                                                                                                           |
| ADM-017 My Admin Profile           | `/admin/my-profile`                        | `GET /auth/me`                                                                                   | Reuses the signed-in identity profile and effective permission response; no duplicate profile endpoint.                                                                                                                                                                                                                                                                                                                     |
| ADM-018 My Sessions                | `/admin/my-sessions`                       | `GET /me/sessions`; `GET /me/sessions/:sessionId`; `DELETE /me/sessions/:sessionId`; `POST /me/sessions/revoke-others` | Implemented as Admin aliases over the shared Module 1 API-token session store. Requires the Admin application, MFA, and own-session permissions. Revocation blocks future API calls with the token; Auth0 SSO/browser sessions must be ended by the client. See the [session API implementation notes](module-1-admin-session-api-gap-analysis.md). |

## Postman flow

The Admin QA and full Postman collections contain the screen flows in dependency order. ADM-018 issues separate local tokens, registers their API sessions, then demonstrates list/detail/revoke/revoke-others and confirms revoked tokens are rejected. The Module 1 collection also has self-service session coverage for the regular demo user. Admin requests inherit the admin token; the local frozen collection obtains a mock admin token from its mock-auth folder. The role-assignment check selects an assignable role the target user did not already have, then revokes only that temporary assignment.

Run the frozen collection after starting `corepack pnpm client:demo`. The local API walkthrough in `scripts/check-client-demo.mjs` exercises all 20 explicit Admin API operations plus expected authorization, change-reason, and optimistic-lock failures.
